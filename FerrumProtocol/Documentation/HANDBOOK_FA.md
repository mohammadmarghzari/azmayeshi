# دست‌کتاب کامل پروژه Ferrum Protocol (فارسی)

این سند برای کسی نوشته شده که هیچ پیش‌زمینه‌ای درباره‌ی Unity یا برنامه‌نویسی بازی ندارد.
هر مرحله را به ترتیب انجام بده.

## این پروژه چیست؟

`Ferrum Protocol` یک بازی استراتژی بلادرنگ (RTS) کاملاً اورجینال است که در پوشه‌ی
`FerrumProtocol/` این ریپازیتوری در حال ساخته‌شدن است (فایل‌های پایتون قبلی
پروژه دست‌نخورده باقی مانده‌اند، این یک پروژه‌ی کاملاً جدا و جدید است).

ساخت یک بازی RTS در حد استودیوهای بزرگ (AAA) معمولاً کار چند سال و ده‌ها نفر
است. این پروژه به‌صورت **فاز به فاز** ساخته می‌شود؛ هر فاز یک پایه‌ی واقعی و
قابل‌اجرا اضافه می‌کند، نه فقط طرح و برنامه. فایل `ROADMAP.md` نقشه‌ی راه کامل
را نشان می‌دهد.

## گام ۱: نصب ابزارها

1. **Unity Hub** را از سایت رسمی یونیتی نصب کن (`unity.com` → Download).
2. داخل Unity Hub، نسخه‌ی **Unity 6000 LTS** (همان "Unity 6") را نصب کن.
   هنگام نصب، این ماژول‌ها را هم تیک بزن:
   - Microsoft Visual Studio (یا صرفاً Visual Studio Code Support)
   - Android Build Support (برای خروجی اندروید)
   - Linux Build Support
   - Windows Build Support (اگر روی مک/لینوکس هستی)
3. یک ویرایشگر کد نصب کن: **Visual Studio Code** پیشنهاد می‌شود.
4. **Git** را نصب کن (اگر قبلاً نصب نکرده‌ای) تا بتوانی پروژه را دریافت/ارسال (pull/push) کنی.

## گام ۲: دریافت پروژه

این ریپازیتوری را کلون کن یا اگر از قبل داری، شاخه (branch) درست را بگیر:

```
git clone <آدرس-ریپازیتوری>
cd azmayeshi
git checkout claude/aaa-rts-game-dev-7osju9
```

## گام ۳: ساخت پروژه‌ی یونیتی و کپی فایل‌ها

چون فایل‌های تنظیمات داخلی یونیتی (`ProjectSettings`) باید توسط خودِ Unity Editor
ساخته شوند تا با نسخه و Render Pipeline درست هماهنگ باشند، این کار را این‌طور انجام بده:

1. در Unity Hub روی **New Project** بزن.
2. تمپلیت **Universal 3D (URP)** را انتخاب کن.
3. اسم پروژه را `FerrumProtocol` بگذار و آن را در یک پوشه‌ی جدید (مثلاً کنار
   همین ریپازیتوری) بساز.
4. بعد از باز شدن یونیتی، پروژه را ببند و این پوشه‌ها را از
   `azmayeshi/FerrumProtocol/` داخل ریپازیتوری، به داخل پوشه‌ی پروژه‌ی جدیدت کپی کن
   (جای‌گزین/ادغام کن، پاک نکن):
   - `Assets/Scripts` → داخل `Assets/`
   - `Assets/Shaders` → داخل `Assets/`
   - `Assets/Scenes`, `Assets/Prefabs`, `Assets/Audio`, `Assets/UI` → داخل `Assets/`
   - محتوای `Packages/manifest.json` را با فایل مشابه پروژه‌ی جدیدت ادغام کن
     (خط‌های `com.mirror...`, `com.unity.ai.navigation`, `com.unity.inputsystem`
     که در پروژه‌ی جدید نیست را اضافه کن).
5. یونیتی را دوباره باز کن. پکیج‌ها به‌صورت خودکار دانلود می‌شوند
   (نیاز به اینترنت دارد).

> چرا این‌طوری؟ چون نوشتن دستی فایل‌های داخلی `.unity`/`ProjectSettings` بدون
> خود Unity Editor می‌تواند پروژه را خراب کند. اسکریپت‌ها و ابزارها را من از قبل
> نوشته‌ام؛ چیزی که باید توسط Unity ساخته شود را خودِ Unity در این مرحله می‌سازد.

## گام ۴: ساخت صحنه‌ی نمایشی (Prototype) با یک کلیک

بعد از باز شدن پروژه:

1. از منوی بالا: **Ferrum Protocol → Build Prototype Scene** را بزن.
2. این کار یک صحنه‌ی کامل (زمین، دوربین RTS، نور، چند واحد و ساختمان نمونه با
   اشکال ساده‌ی هندسی به‌جای گرافیک نهایی) می‌سازد و ذخیره می‌کند.
3. دکمه‌ی **Play** بالای صفحه را بزن. حالا باید بتوانی:
   - با اسکرول موس زوم کنی
   - با نگه‌داشتن دکمه‌ی وسط موس یا Q/E بچرخانی
   - با کشیدن موس به لبه‌ی صفحه یا کلیدهای جهت‌دار/WASD حرکت کنی
   - با کلیک چپ واحدها را انتخاب کنی، با کشیدن مستطیل چند واحد را انتخاب کنی
   - با کلیک راست به آن‌ها دستور حرکت/حمله بدهی

اگر خطای Compile (قرمز در پایین صفحه‌ی Console) دیدی، متن کامل خطا را برایم
بفرست تا در فاز بعدی رفعش کنم — من در همین محیط ابری Unity Editor نصب ندارم،
پس اولین کامپایل واقعی همین‌جا، در سیستم خودت، اتفاق می‌افتد.
